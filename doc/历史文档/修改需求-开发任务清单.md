# A-Level 升学系统 — 修改需求开发任务清单

> 依据：`doc/历史文档/修改需求.md` 及 2026-04 业务确认答复。  
> 目标：**Web 端高效、交互简洁、信息直观**，便于**教师**日常使用，**家长**也能快速读懂关键进展。  
> 范围说明：原需求 **第 16 条（待办窗口 / 与智能行动计划合并）** 按约定 **暂不开发**。

---

## 一、业务与数据口径（先于开发写清）


| 任务 ID      | 内容                                                           | 产出                            |
| ---------- | ------------------------------------------------------------ | ----------------------------- |
| **BIZ-01** | **年级 = 入学年份**：统一界面文案、字段含义（与「届别」「在读年级」口语区分）。                  | 数据字典片段 + 学生/列表/仪表盘展示规则说明。     |
| **BIZ-02** | **预毕业时间**：精确到 **月（YYYY-MM）**；与 **学制（2 年制 / 3 年制）** 可切换。      | 字段定义、校验规则、与申请时间线/考季的展示关系（若有）。 |
| **BIZ-03** | **学制切换后的「数据联动」**：明确范围（时间线、考季、任务截止日期是否按比例/规则重算，或仅更新「毕业相关展示」）。 | 联动规则文档（避免开发时各写各的）。            |


**整合建议**：在「学生基本信息」卡片用一行 **「入学 · 学制 · 预毕业」** 固定顺序展示，家长扫一眼即可；教师用编辑表单维护，减少分散在多处。

| 任务 ID     | 对应需求 | 任务描述                                                                                                      | 验收要点                              |
| --------- | ---- | --------------------------------------------------------------------------------------------------------- | --------------------------------- |
| **P0-01** | 原 7  | **选课列表为空**：修复课程筛选逻辑 — 学生可选课程 = `grade_level` 等于 **学生入学年份** 或课程为 `**ALL`**（及后端/前端参数命名与 `BIZ-01` 一致）。       | 新建课程后，成绩管理「添加选课」可见；考季依赖选课的流程可继续。  |
| **P0-02** | 原 11 | **仪表盘切换年级/学生数据错乱**：`activeGrade` / 路由 `id` 变化时，loading、当前学生合法性、`lastViewedStudentId` 与年级列表同步；避免展示过期仪表盘数据。 | 快速切换年级与学生，无空白错数据；无需靠「去学生管理再回来」恢复。 |
| **P0-03** | 原 5  | **课程/单元弹窗内偶发无法输入**：按复现路径排查 `Dialog` + 受控组件（焦点、`modal`、`key` 重置表单等）。                                       | 连续打开/关闭、新建/编辑后仍可正常输入。             |

| **P0-05** | 原 9  | **逾期待办**：截止日早于今日且未完成的任务 — **醒目样式 + 简短说明文案**。                                                              | 列表与（若有）详情一致；不误伤「无截止日期」任务。         |

## 三、阶段 P1 — 学生档案、课程与导航


| 任务 ID     | 对应需求   | 任务描述                                                                                                               | 验收要点                          |
| --------- | ------ | ------------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| **P1-01** | 答复 1–2 | **学生表与表单**：以 **入学年份** 为年级主数据；新增 **预毕业年月**；新增 **学制（2/3 年）** 切换。切换学制时按 **BIZ-03** 实现已承诺的联动。                          | 列表/详情/导出口径一致；切换学制后相关模块行为符合文档。 |
| **P1-02** | 原 3、4  | **课程管理**：提供修改 **课程名称**（不仅是单元名）；新建/编辑课程可改 **学年/年份相关字段**（与现有 `academic_year`、`semester` 等字段对齐）。                      | 改名后选课、成绩、仪表盘课程名一致。            |
| **P1-03** | 答复 3   | **顶层入口**：主导航增加 **成绩管理**、**考季规划**（或统一命名），进入 **当前正在查看的学生** 对应子页（`StudentDetail` 的 `tab=` 或等价路由）。无当前学生时定义降级（如提示先选学生）。 | 教师少点几次即可到常用 Tab；路径可收藏。        |


**整合建议**：导航两项使用 **同一学生上下文**（与仪表盘当前 `studentId` 同步），避免「点进去是另一个学生」；无学生时 **统一空状态**：「请先在学生管理或仪表盘中选择学生」。

## 四、阶段 P2 — 院校库、目标院校与匹配逻辑


| 任务 ID     | 对应需求        | 任务描述                                                                                                                                                                                        | 验收要点                                |
| --------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| **P2-01** | 原 12        | **院校库专业 — A-Level 成绩要求**：当前按钮组为「去重数组」导致无法表达 **多科同等级**（如 AAA）。改为可表达真实组合的方案（例如：**按科槽位**、或 **可重复选择的等级序列** + 预览字符串）。                                                                            | 与招生简章常见写法一致；保存/回显正确。                |
| **P2-02** | 原 13        | **学生目标院校 ↔ 专业**：`student_universities`（或扩展表）关联 **院校库中的专业/program**；学生端选目标时可选专业。                                                                                                             | 列表、详情、仪表盘显示所选专业。                    |
| **P2-03** | 答复 4        | **默认匹配数据源**：**新建学生** 时，仪表盘院校匹配默认使用 **第一个冲刺院校（reach）**；若无则再降级（顺序写清）。                                                                                                                         | 新学生打开仪表盘即有合理默认匹配对象。                 |
| **P2-04** | 原 10 + 答复 4 | **匹配判定覆盖（长期保存）**：提供 UI 指定 **语言/标化等待用记录**（按你的规则持久化，如 `student_id` + `target_university_id` 或 `student_university_id` 存所选 `language_score_id` / `standardized_test_id`）；**仪表盘所有相关匹配展示**读取该配置。 | 切换保存后刷新仪表盘即生效；老数据有默认策略（如「该类型最佳成绩」）。 |


**整合建议**：匹配设置放在 **「目标院校」区块内联** 或 **「匹配设置」小面板**，避免家长看到满屏技术项；默认不展开，教师展开后配置。

## 五、阶段 P3 — 语言能力展示与申请进度细化


| 任务 ID     | 对应需求        | 任务描述                                                                                                                                                                  | 验收要点                           |
| --------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| **P3-01** | 原 14        | **语言能力「平行判定」**：按 **考试类型**（IELTS、TOEFL 等）分别展示 **该类型下的最佳**；与 **P2-04** 手动指定共存（手动优先或作为覆盖规则，在实现时二选一并写清）。                                                                  | 不再出现「只看第一个 best」的歧义。           |
| **P3-02** | 原 15 + 答复 5 | **申请进度 — 已录取细分**：区分 **无条件录取** / **条件录取**；子字段 **均可选填** — 建议合并进现有 `student_universities`：扩展 `status` 或使用结构化 JSON（如 `offer_detail`）存放：无条件 — DDL、其他；条件 — 学术、语言、押金、DDL、其他。 | 仪表盘时间线/卡片能区分两类 offer；未填项不强行占位。 |


**整合建议**：与现有 `conditions` 字段：**合并为一块「录取详情」** 更利于维护，迁移脚本把旧纯文本 `conditions` 迁入「其他」或保留只读历史；界面用 **折叠区** 减少家长信息过载。

## 九、需要你或教务最终确认的一次性决策（实现前）

1. **入学年份** 存储形态：四位数字 `2024` 与界面「2024级」是否 **同一字段两种展示**，避免双字段不同步。我的确认：是的，一种字段两个展示；
2. **学制切换** 「各项数据一起变动」是否包含：**已录入的考试日期**、**任务 deadline** — 若包含，用 **平移月数** 还是 **仅重算展示用的「届别/阶段」**？我的确认：不包含已录入的**考试日期**、**任务 deadline**
3. **第一个冲刺院校** 的排序：是否严格以 `application_type === 'reach'` 且 **创建顺序 / 手动排序** 取第一个？需在 UI 上可理解（如「拖拽排序」后续可做，本期可固定规则）。我的确认：按照创建顺序的第一个。
