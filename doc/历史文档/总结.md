### 1）“重考/补考科目”现在是怎么判断的（代码口径）
当前项目里 **“需补考/需重考”** 的判定来自 `Dashboard.tsx` 对每个课程的 `final` 类型单元成绩做扫描：

- **单科 needsRetake**：只要该科的“实考单元”（`exam_type === 'final'`）里 **出现等级为 `D / E / U`**，就判定该科 `needsRetake = true`
- **retakeUnits**：把这些 `D/E/U` 的单元名（`unit_code` 或 `unit_name`）收集出来

等价表达：

- \(\text{needsRetake} = \exists u \in \text{finalUnits},\ u.grade \in \{D,E,U\}\)
- \(\text{retakeUnits} = \{u.unit \mid u \in \text{finalUnits},\ u.grade \in \{D,E,U\}\}\)

注意点（很关键）：
- 它**不会**因为校内成绩低就判定补考；只看 **实考单元 grade**
- 如果你们录入的是**分数但没录入 grade**，那也不会触发补考（因为判断依赖 grade）
- 如果某科只有校内成绩（`exam_type=internal`），那 `needsRetake` 基本不会被触发

### 2）“目标院校匹配度”现在怎么计算的（代码口径）
匹配度主要在 `GoalsAndActions.tsx`（同逻辑也出现在 `UniversityMatchPanel.tsx`），每所院校一个分数，三部分加权：

#### **(1) 学术匹配 40%**
- 从院校 `A-Level要求` 字符串里用正则抓 `A* A B C D` 这些字母
- 把字母映射成分数：`A*→95, A→85, B→75, C→65, D→55`
- 求“要求均分” `avgRequired`
- 再算学生当前各科的“当前分数”（见下文第3部分的取值规则），求均分 `avgCurrent`
- 学术部分得分：\(\min(\frac{avgCurrent}{avgRequired}\times 100, 100) \times 0.4\)

#### **(2) 语言匹配 30%（IELTS）**
- 只取 `languageScores` 里 `IELTS && bestScore=true` 的总分
- 从院校语言要求字符串里取第一个数字当作要求（例如 “IELTS 7.0(6.5)” 会取到 7.0）
- 语言部分得分：\(\min(\frac{IELTS}{IELTS_{req}}\times 100, 100) \times 0.3\)

#### **(3) 申请状态 30%（进度加成）**
- offer：加 `100 * 0.3`
- submitted：加 `80 * 0.3`
- preparing：加 `50 * 0.3`
- 其他状态：加 0

最后再除以总权重并转百分制（实现里写法有点“权重/百分比混用”，但结果就是 0~100 的百分数）。

重要点（你要知道它的局限）：
- **不看“必修科目/科目组合”**（比如“必须数学A*、必须进阶数学”这类要求只是文本提示，不参与数值）
- **A-Level要求解析很粗糙**：只按字母平均，不区分 A*AA vs AAA，也不区分“数学必须A*”
- **语言要求只取第一个数字**，没有处理小分
- 申请状态给了 30% 权重，容易“进度高但硬实力不够也拉高匹配度”

### 3）你截图里这块“总览/各科/语言能力/申请进度”的得分怎么来的
这块对应 `CompetencyAnalysis.tsx` 的“维度得分”卡片（总览 + 每个科目 + 语言能力 + 申请进度），以及 `CoreMetricsPanel.tsx` 的“整体就绪度”。

#### **(A) 单科卡片上的分数（如 Mathematics 70）**
每个学科分数来源是 `getSubjectScore`（多个地方复用），取值优先级：

1. `computedFinalScore`（有实考单元时的合成百分制）
2. `computedInternalAvg`（最近两次校内考试均分，百分制）
3. `finalScore`（总评字段）
4. `mockScore`
5. `internalScore`
6. 都没有则 `0`

其中：
- `computedFinalScore` 在 `StudentDetail.tsx` 的课程详情展示里是按 final 单元得分/满分合成：
  \(\text{computedFinalScore}=\text{round}(\frac{\sum score}{\sum maxScore}\times 100)\)
- `computedInternalAvg` 是最近两次 `internal` 单元的百分比均值：
  \(\text{computedInternalAvg}=\text{round}(\frac{1}{n}\sum \frac{score}{maxScore}\times 100)\)，\(n=最近2次\)

#### **(B) 单科卡片右侧的红色“偏差 -13”**
这在 `CompetencyAnalysis.tsx` 里叫 deviation：
- 只有当 **computedFinalScore 和 computedInternalAvg 都存在** 才显示
- 计算：`computedFinalScore - computedInternalAvg`
- 负数表示实考比校内均分低（你截图里就是这种）

#### **(C) “总览 31”**
`CompetencyAnalysis.tsx` 的 overallScore：
- 先算各科平均分 `avgSubjectScore`（只取 subject 维度）
- 再算语言维度：`语言能力 = round( bestLanguage.overall / 9 * 100 )`
- 申请维度：`申请进度 = round( submittedOrOffer / totalTargetUni * 100 )`
- 综合：`overall = round( avgSubjectScore*0.5 + language*0.3 + application*0.2 )`

因此你截图里“语言能力 0 / 申请进度 0”会把总览大幅拉低。

#### **(D) CoreMetricsPanel 里的“整体就绪度”（另一个总分）**
`CoreMetricsPanel.tsx` 的 readiness：
- 学术：把各科分数求平均，映射到 `avg/90*100`（90 视作满配学术水平）
- 语言：`IELTS/7.5*100`
- 申请：submitted/total *100
- 再做 50/30/20 加权

这就是你看到“整体就绪度学术50%·语言30%·申请20%”。

## 让系统更“实用、方便升学中心跟进”的几套思路（给你多方案选）
下面不是泛泛建议，都是对你现有数据结构/页面能落地的方向。

### 思路A：把“补考/重考”从“被动判定”升级成“备考计划驱动”
- **现状问题**：现在只靠 `D/E/U` 才提示补考，太晚；且不看“下个考季/报名截止”
- **改进**：
  - 对每个 `course_unit` 增加：`target_grade / target_score / planned_session / plan_type(first_sit/resit) / deadline`
  - 页面上以“考季”为主视角（你们已有 `ExamSessionPlanner` 数据结构），生成：
    - 哪些单元必须 resit
    - 哪些单元还没安排 first sit
    - 报名截止倒计时 + 风险灯
- **产出**：升学中心能直接按“考季计划清单”推进，而不是看一堆分数

### 思路B：匹配度改为“硬门槛 + 量化评分”两层结构
- **现状问题**：匹配度把进度也算进去，且不识别必修科目要求
- **改进**：
  - 先做 **硬门槛判定**（fail-fast）：
    - 是否有必修课（数学/进阶数学/理科）
    - 语言是否达标（含小分）
    - 是否需要额外考试（MAT/STEP/TMUA…）
  - 再做 **量化评分**（只在硬门槛通过后计算）：
    - 学术：按“相关科目”加权（经济学看 Math+Econ，CS 看 Math+FM+Physics）
    - 语言：按小分最短板
    - 进度：不要混进匹配度，单独显示“申请推进度”
- **产出**：匹配度才会“像录取概率/可行性”，升学中心不会被误导

### 思路C：把“校内成绩”与“实考成绩”分离呈现，并做趋势/可靠度
- **现状问题**：一个分数混合了 internal/final，且 internal 只取最近两次，容易抖动
- **改进**：
  - 每科展示三条线：`校内（近N次均值）/模考/实考`
  - 给出“可靠度”标识（例如：实考>=2单元才可信，校内>=3次才可信）
  - 在卡片上显示：`预测分`（用回归或简单偏差修正：final ≈ internal + 平均偏差）
- **产出**：更像“学术监控面板”，能指导教学干预

### 思路D：升学中心的“工作台”而不是“学生主页”
- 以升学中心每天的工作为主：  
  - “本周需要跟进的学生”列表（触发条件：补考单元未安排/语言未达标/关键DDL<30天）
  - 一键生成任务（你们已有 tasks）
  - 任务完成率、逾期率、风险学生数
