# IG–A Level 界面设计基线

## 1. 设计目标

  本次升级把网站从“围绕单个学生查看数据”扩展为“学校组织课程、教师执行教学、学生完成选课与学习”的一体化工作台。界面继续使用现有组件和品牌素材，重点重组信息层级与操作路径，不另造一套平行设计系统。

## 3. 信息架构

| 工作区 | 主要使用者 | 核心任务 |
|---|---|---|
| 学校总览 | 管理员、教务 | 查看 9–12 年级覆盖、待审选课、排课冲突、教师负荷、考试窗口 |
| 学生 | 教务、指导老师、教师 | 查找学生、查看学段记录、成绩、考季与升学档案 |
| 课程与大纲 | 教务、课程负责人 | 维护学校开课与已核验的考试局规范版本 |
| 选课 | 学生、教师、教务 | 填报志愿、检查容量与冲突、审核并形成教学班名单 |
| 教学班 | 教务、教师 | 管理班额、教师、学生名单与周课时要求 |
| 排课 | 教务、管理员 | 管理草案、约束、冲突、人工锁定、发布与回退 |
| 考试 | 教务、教师、学生 | 查看考季、单元计划、报名与重要时间点 |
| 升学指导 | 学生、指导老师 | 保留现有院校、任务、语言和申请功能 |
| 权限与审计 | 管理员 | 管理账号职责并查看关键操作记录 |

## 4. 设计令牌与组件规则

| 项目 | 规则 |
|---|---|
| 背景 | 页面使用纯白/接近白的开放背景；不使用大面积米黄或装饰渐变 |
| 主色 | 深海军蓝用于导航和标题；低饱和青绿用于当前状态与主要动作 |
| 风险色 | 黄色表示待关注，红色只表示阻断发布的硬冲突或危险操作 |
| 容器 | 表格、时间网格和列表优先；仅汇总与独立操作区使用卡片 |
| 边框 | 1px 低对比度分隔线；避免多层阴影和悬浮卡片墙 |
| 圆角 | 控件 8px，主要容器 10–12px；排课网格保持紧凑直角结构 |
| 字体 | 系统中文无衬线用于工具界面；数字使用等宽数字特性 |
| 图标 | 沿用 Lucide 线性图标，语义统一，不使用文本字符代替箭头或状态图标 |

## 5. 关键交互

  学校总览中的数字必须进入对应工作区并保留筛选条件。排课冲突必须同时显示发生对象、时间、原因和修复入口；仅显示“共 N 个冲突”不算完成。

  排课以草案为基本单位。自动排课不得直接发布，教务可以锁定已确认课节、手动调整、重新检查，并在零硬冲突后发布。发布动作必须记录人员、时间、版本和说明。

  学生选课在提交前即时展示容量与已发布课表冲突。第一、第二志愿属于同一选择组，系统不得把两个志愿都当成最终选课。学校审核拥有最终决定权，且审核结果需要保留原因。

## 6. 响应式边界

  桌面端是排课和批量教务操作的主环境。窄屏下学校总览与选课可以改为上下布局；周排课网格保留横向滚动和固定时间列，不压缩到不可读。移动端允许学生查看和提交选课，但不承诺完成复杂的人工排课编辑。
