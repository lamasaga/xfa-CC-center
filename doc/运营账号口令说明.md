# 运营账号口令说明

## 重置为强口令

　　管理员（`admin`）、教务（`staff`）、指导老师（`supervisor`）的密码存储为 bcrypt 摘要，**不会**在代码或数据库中保留可逆明文。需要统一改为强口令并本地留存时，在 **`app` 目录**执行：

```powershell
Set-Location "d:\你的路径\Alevelinfo\app"
npm run reset-staff-passwords
```

　　脚本会：

- 为上述三个用户名各生成一段随机强口令（或使用下方环境变量指定）；
- 更新当前 `SQLITE_PATH` 指向的 SQLite 库（未设置时默认 `app/database.sqlite`）；
- 在仓库根目录 **`doc/运营账号口令-本地留存.md`** 写入表格（**明文**）。

　　可选：仅预览不写库：

```powershell
node server/scripts/reset-staff-passwords.cjs --dry-run
```

　　可选：自行指定明文（避免随机）：

| 环境变量 | 作用 |
|----------|------|
| `RESET_ADMIN_PASSWORD` | 管理员新口令 |
| `RESET_STAFF_PASSWORD` | 教务新口令 |
| `RESET_SUPERVISOR_PASSWORD` | 指导老师新口令 |

## 登录失败时建议自检

　　从 `运营账号口令-本地留存.md` 复制口令时，**只复制反引号内的字符**，不要带上表格竖线、前后空格或换行。若误把 Markdown 成对的反引号一起粘进密码框，服务端会尽量自动剥掉一层；仍建议只复制中间明文。

　　自脚本更新起，**新生成**的随机口令不再包含 `%`、`$`、`=` 等易与 Markdown、Shell、代理混淆的字符；**旧口令**仍有效，无需因字符种类而改密。

　　浏览器若曾保存旧 JWT，会出现 **`/api/auth/me` 403（Invalid or expired token）** 或 **`/api/auth/me` 404**（库与 token 不一致等）。请在开发者工具 → Application → Local Storage 中**删除 `token`（及可选 `user`）**，再重新登录。

　　若修改过环境变量 **`JWT_SECRET`**，旧 token 一律失效，同样需要清除本地 `token` 后重新登录。

## 首次建库时的种子口令

　　全新空库首次 `initDb` 时，仍会为 `admin` / `staff` / `supervisor` 插入种子用户。默认口令为开发用弱口令；生产或正式环境建议在**第一次启动前**设置：

| 环境变量 | 作用 |
|----------|------|
| `SEED_ADMIN_PASSWORD` | 首次建库管理员口令 |
| `SEED_STAFF_PASSWORD` | 首次建库教务口令 |
| `SEED_SUPERVISOR_PASSWORD` | 首次建库指导老师口令 |

　　未设置时行为与原先一致（`admin123` / `staff123` / `supervisor123`），便于本地与 CI 冒烟测试。

## 安全提示

　　`doc/运营账号口令-本地留存.md` 已列入仓库根目录 **`.gitignore`**，请勿手工取消忽略后提交。更稳妥的做法是把口令只放进密码管理器，并删除或清空该 Markdown 文件。
