# 线上更新与数据库维护纪要

　　**文档日期**：2026-04-21  
　　**适用范围**：本仓库 Alevelinfo 应用；服务器示例为 Ubuntu、`systemd` 单元 **`alevelinfo`**、应用目录 **`/opt/alevelinfo/app`**、SQLite 默认路径 **`/opt/alevelinfo/app/database.sqlite`**（若你实际使用 `SQLITE_PATH` 或挂载卷，以运行中配置为准）。

　　本文是对近期上线与运维工作的**操作向摘要**；细节与原理见文末索引中的既有文档。

---

## 一、如何更新网站内容（代码与前端资源）

　　**推荐方式**：在 **Windows PowerShell** 于本机仓库中执行一键脚本（会打包 **`app`** 目录、排除 `node_modules`、`dist`、本地库文件、`.env*`、`.git` 等，再上传并在服务器执行构建与重启）。

```powershell
Set-Location "D:\1XFAwork\highSCHOOL\A-levelCENTER\Alevelinfo"
.\deploy\upload-and-update.ps1 -Server "你的公网IP或域名" -IdentityFile "$env:USERPROFILE\.ssh\你的私钥文件名"
```

　　**要点**：

- **`-Server`**：必填；**`-IdentityFile`**：若平时用 `ssh -i` 登录，建议显式传入，与 `scp`/`ssh` 一致。  
- 脚本依赖本机 **OpenSSH**（`ssh`/`scp`）及 **Windows 自带 `tar.exe`**。  
- **Windows PowerShell 5.1** 下，请将 **`deploy\upload-and-update.ps1`** 保存为 **带 BOM 的 UTF-8**，否则含中文的脚本可能出现解析错误（详见当时排障记录）。  
- 远端会 **`systemctl stop`** → 备份 SQLite（若存在）→ 解压覆盖 → **`npm ci` / `npm run build` / `npm rebuild better-sqlite3`** → **`systemctl start`**。  
- **上传不会携带** 项目里的 **`.env` / `JWT_SECRET`**；生产环境密钥必须在 **`systemd` 的 `Environment=`** 中配置（见第二节）。

　　**说明**：若远端更新脚本失败，本机脚本仍可能打印「全部完成」；应以 **`systemctl status alevelinfo`** 与 **`journalctl -u alevelinfo`** 为准。

## 二、维护运行环境：生产环境 `JWT_SECRET`

　　当 **`NODE_ENV=production`** 时，应用要求环境变量 **`JWT_SECRET`** 存在、非空、非占位弱值，且长度满足代码中的下限（见 `app/server/config.js`）。未配置时进程会在启动阶段直接退出，表现为 **`activating (auto-restart)`**、本机 **`curl 127.0.0.1:3001` 连接被拒绝**。

　　**配置位置**：`/etc/systemd/system/alevelinfo.service` 的 **`[Service]`** 段，例如单独一行（密钥请自行生成并妥善保管）：

```ini
Environment="JWT_SECRET=此处为足够长的随机串"
```

　　修改后执行：

```bash
sudo systemctl daemon-reload
sudo systemctl restart alevelinfo
sudo systemctl show alevelinfo -p Environment --no-pager
```

　　确认输出中含 **`JWT_SECRET=`** 且服务 **`active (running)`**。**轮换 `JWT_SECRET` 后**，所有已签发登录态失效，用户需重新登录。

## 三、维护网站数据库：与「上传」的关系及账号口令

　　**上传更新的是代码**；服务器上的 **`database.sqlite`** 是**独立数据文件**，除非脚本或人工覆盖，否则**不会**被开发机上的库替换。

　　**`doc/运营账号口令-本地留存.md`** 中记录的口令，对应的是**生成该文件时所指向的那份 SQLite**（文档内会写明路径）。若在**本机**运行 `npm run reset-staff-passwords` 生成口令，则**只更新本机库**；要在**线上**使用相同流程重置 **admin / staff / supervisor**，需在服务器应用目录执行：

```bash
cd /opt/alevelinfo/app
npm run reset-staff-passwords
```

　　（仅预览可加 `--dry-run`。）线上生成后的留存路径可能位于 **`/opt/alevelinfo/doc/`**（与脚本解析路径有关），请以命令输出为准。

　　**备份与恢复、WAL 热备、cron 示例**等，仍以 **`doc/服务器数据库备份与维护.md`** 为权威说明；其中若示例路径为 `/opt/alevelinfo/data/`，请按你实际 **`SQLITE_PATH` / 文件落盘位置**改写。

　　**周备份示例思路**：安装 **`sqlite3`** CLI，用 **`.backup`** 对线上库做一致快照，将备份写入专用目录（权限 **700**、勿放在 Web 可下载路径），再用 **`cron`** 例如每周固定时刻执行脚本；轮转删除过旧文件，避免占满磁盘。

## 四、自检命令（服务器 SSH 内）

```bash
sudo systemctl status alevelinfo --no-pager -l
curl -sS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3001/
sudo journalctl -u alevelinfo -n 40 --no-pager
```
