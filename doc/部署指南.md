# A-Level 升学管理系统 — 轻量云部署指南（推荐：Docker Compose）

适用范围：当前仓库 `app/` 目录下的 **React + Vite（构建后静态） + Express（API + 静态托管） + SQLite(better-sqlite3)** 一体应用。

目标形态：

```text
浏览器 → HTTPS(443) → Nginx(宿主机) → http://127.0.0.1:3001 → Node/Express（同时提供页面与 /api）→ SQLite 文件
```

---

## 0. 你需要准备什么

- 一台轻量云（推荐 Ubuntu 22.04/24.04，同类 Linux 亦可）
- 一个域名（可选但强烈建议；上 HTTPS 会更省心）
- 一台你本地开发电脑（用于推代码/SSH）

> 重要约束：`better-sqlite3` 包含原生二进制，**必须在目标系统（Linux）上安装/重建**，不要在 Windows 构建后把 `node_modules` 整包上传。

---

## 1. 部署策略选择

本指南主线使用 **Docker Compose**，优点是环境可复现、迁移机器更容易。

如果你更偏好传统方式（在服务器安装 Node + systemd），见文末「附录 A」。

---

## 2. 服务器初始化（只做一次）

### 2.1 基础安全与网络

- 仅开放端口：**22 / 80 / 443**
- 建议：
  - 禁止 root 密码直登，改用 SSH key
  - 开启基础防火墙（UFW/安全组），不要把 3001 暴露到公网

### 2.2 安装 Docker 与 Compose

不同发行版命令略有差异，你可以按云厂商文档安装。安装完成后应满足：

```bash
docker --version
docker compose version
```

---

## 3. 部署目录约定（推荐）

在服务器上统一放到：

```text
/opt/alevelinfo/
  ├─ app/                # 本仓库的 app 目录（包含 server/、src/、package.json 等）
  ├─ deploy/
  │   ├─ docker-compose.yml
  │   ├─ .env            # 只放服务器，不提交仓库
  │   └─ nginx/
  │       └─ alevelinfo.conf
  └─ data/
      └─ database.sqlite # SQLite 持久化文件（建议放到独立目录）
```

> 如果你现在的 `app/database.sqlite` 已经有真实数据，建议先把它复制到 `/opt/alevelinfo/data/database.sqlite` 再切换到新结构。

## 4. 代码同步（两种方式选一种）

### 方式 A：服务器直接拉代码（推荐）

在服务器安装 git，然后：

```bash
cd /opt/alevelinfo
git clone <你的仓库地址> repo
```

再把 `repo/app/` 作为部署源（也可以只复制 `app/`）。

### 方式 B：本地打包上传

只上传源码（不要上传 `node_modules`、不要上传本地构建的二进制），例如上传 `app/` 目录的源码到服务器。

## 5. Docker 方式部署（主线）

### 5.1 环境变量（服务器 `deploy/.env`）

在服务器创建 `/opt/alevelinfo/deploy/.env`，至少包含：

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=3001

# 必填：用于签发 JWT。上线后不要随意改，否则用户需要重新登录
JWT_SECRET=请替换为长随机字符串
```

> 注意：不要把真实 `JWT_SECRET` 提交到仓库。只在服务器保存。

### 5.2 Dockerfile（放在 `app/` 内）

如果你未来希望“一条 compose”完成构建+运行，推荐在 `app/` 目录提供一个 Dockerfile（若你已经有，按现有为准）。

典型思路（说明性示例）：
- 在镜像内执行 `npm ci`
- `npm run build` 产出 `dist/`
- `npm rebuild better-sqlite3`（确保 Linux 原生模块可用）
- `node server/index.js` 启动

> 是否需要我在代码里补齐 Dockerfile：可以，但这属于代码变更。本次先把指南写全，你确认后我再把 Docker 相关文件补进仓库会更稳。

### 5.3 `docker-compose.yml`（服务器 `deploy/docker-compose.yml`）

下面是一个**常用模板**，你需要把 `<PATH_TO_APP>` 替换成服务器上实际路径（例如 `/opt/alevelinfo/repo/app`）。

```yaml
services:
  web:
    build:
      context: <PATH_TO_APP>
    env_file:
      - .env
    restart: unless-stopped
    ports:
      - "127.0.0.1:3001:3001"
    volumes:
      # SQLite 持久化：把数据库文件放到宿主机 data/ 下
      - /opt/alevelinfo/data/database.sqlite:/app/database.sqlite
```

关键点：
- `ports` 只绑定到 `127.0.0.1`，对公网不可见，公网入口交给 Nginx(443)
- `database.sqlite` 用宿主机文件持久化，容器重建不会丢数据

### 5.4 首次启动（服务器）

```bash
cd /opt/alevelinfo/deploy
docker compose up -d --build
docker compose ps
```

### 5.5 首次初始化数据库（如果你是空库）

如果服务器上还没有 `database.sqlite`，你需要初始化一次。两种方式：

- **方式 A：在容器里执行**（推荐一致性）

```bash
cd /opt/alevelinfo/deploy
docker compose exec web node server/init-db.js
docker compose exec web node server/migrate-data.js
```

- **方式 B：直接用容器启动时自动创建**

取决于你项目 `server/init-db.js` 是否会自动创建/安全退出（以当前代码行为为准）。

## 6. Nginx 反向代理 + HTTPS

### 6.1 Nginx 安装

```bash
sudo apt update
sudo apt install nginx
```

### 6.2 站点配置（示例）

创建 `/etc/nginx/sites-available/alevelinfo.conf`：

```nginx
server {
    listen 80;
    server_name your.domain.com;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用并检查：

```bash
sudo ln -s /etc/nginx/sites-available/alevelinfo.conf /etc/nginx/sites-enabled/alevelinfo.conf
sudo nginx -t
sudo systemctl reload nginx
```

### 6.3 HTTPS（Let’s Encrypt）

推荐使用 `certbot` 自动签发/续期证书（以你服务器发行版教程为准）。

完成后应满足：
- `http://your.domain.com` 自动跳转到 `https://your.domain.com`
- 浏览器显示证书正常

## 7. 发布更新（最常用）

当你在本地开发完成并把代码更新到服务器后：

```bash
cd /opt/alevelinfo/deploy
docker compose up -d --build
```

如果更新涉及依赖或 native 模块，`--build` 必不可少。

## 8. 备份与恢复（SQLite 必做）

### 8.1 备份策略

最小可行策略：
- 每天定时备份 `/opt/alevelinfo/data/database.sqlite`
- 至少保留 7 天
- 备份文件最好同步到异地（对象存储/另一台机器）

备份命令（示例）：

```bash
cp /opt/alevelinfo/data/database.sqlite "/opt/alevelinfo/backup/database.sqlite.$(date +%F)"
```

> SQLite 在 **WAL 模式** 下，仅 `cp` 主文件不一定得到一致快照。更稳做法见 **[服务器数据库备份与维护.md](./服务器数据库备份与维护.md)**（`sqlite3 .backup`、停服复制、cron 与恢复演练）。

### 8.2 恢复流程（要演练）

1. 停止服务：

```bash
cd /opt/alevelinfo/deploy
docker compose down
```

2. 用备份覆盖数据库文件（确保路径正确）：

```bash
cp /opt/alevelinfo/backup/database.sqlite.YYYY-MM-DD /opt/alevelinfo/data/database.sqlite
```

3. 启动服务：

```bash
docker compose up -d
```

## 9. 上线检查清单（建议按顺序打勾）

- **网络**
  - 服务器只开放 22/80/443
  - 3001 未对公网暴露（只能本机访问）
- **应用**
  - 首页可打开，静态资源 200
  - 登录正常，调用 `/api/*` 正常
  - 重启服务器后服务能自动拉起（Docker restart 策略生效）
- **安全**
  - HTTPS 正常、证书自动续期已配置
  - `JWT_SECRET` 为强随机且只在服务器保存
- **数据**
  - `database.sqlite` 已持久化到宿主机路径
  - 备份任务已配置并验证可恢复

## 10. 常见问题速查

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| `better-sqlite3` 报错 | 未在 Linux 目标环境 rebuild | 用 Docker 构建镜像，或在服务器执行 `npm rebuild better-sqlite3`（推荐容器内构建） |
| 外网访问不了 | 安全组/防火墙没放行 80/443；Nginx 未 reload | 检查云控制台安全组与 `nginx -t` |
| 页面空白/资源 404 | 未构建 dist 或工作目录不对 | 确认容器内有 `dist/`，并由 Express 正确托管 |
| 大量 401 | `JWT_SECRET` 变更导致旧 token 失效 | 固定 `JWT_SECRET`，必要时让用户重新登录 |

## 附录 A：不用 Docker 的部署思路（systemd + Nginx）

核心步骤：
- 服务器安装 Node LTS
- 在服务器 `app/` 目录执行 `npm ci`、`npm run build`、`npm rebuild better-sqlite3`
- 用 systemd 托管 `node server/index.js`（环境变量从 systemd service 注入）
- Nginx 反代到 `127.0.0.1:3001`，对外只开放 80/443
