## 4. 自动发布过程

  Windows 端执行 `deploy/upload-and-update.ps1`。脚本依次构建院校探索站、同步 `study-dist`、重新安装主站依赖、运行 API 测试、构建主站、打包并上传候选版本；每个外部命令都会核对退出码，任何本地校验失败都会立即停止发布。

  若服务器只有公网 IP，先执行 `deploy/enable-ip-https.sh <公网IP>`。该脚本使用 Certbot 5.4 以上版本申请 Let's Encrypt 约六天有效的 IP 短期证书，保留 HTTP-01 验证目录、将 80 端口重定向到 443，并安装续期后重载 Nginx 的 hook。短期证书必须依赖自动续期，不能把一次签发视为长期完成。

  服务器端 `deploy/remote-update.sh` 执行以下步骤：

1. 服务保持运行，创建生产数据库一致性预检备份并校验哈希。
2. 在独立 release 目录解压、安装依赖和构建，不覆盖当前应用。
3. 复制预检备份，在副本上执行 `001_ig_alevel_integration.sql` 和 `002_secure_sessions.sql`，再做完整性检查。
4. 保存当前完整应用目录作为代码回滚副本。
5. 短暂停止服务，创建最终一致性数据库备份。
6. 使用 `rsync` 切换代码，明确保留数据库、WAL、上传文件和 `.env`。
7. 启动服务并重试本机 `/api/health` 健康检查。
8. 若停服后的任一步骤失败，自动恢复旧代码和最终数据库备份，再启动服务。

## 5. 数据迁移原则

  两个迁移文件只新增表、约束和索引，不删除或改写现有学生、课程、成绩、考试、任务或院校表。启动时 `schema_migrations` 只记录成功完成的版本；同一版本不会重复执行。

  `student_academic_records` 是新的年度学段事实源。旧 `students.grade` 继续保留，界面明确标注为入学届或历史字段，不根据它自动推测 9–12 年级。上线后由教务逐步补录当前学年记录。

## 6. 上线后冒烟清单

| 角色 | 验收动作 | 预期结果 |
|---|---|---|
| 管理员 | 登录并打开学校总览 | 旧学生数据仍在；9–12 年级未补录处显示“待录入”，不伪造人数 |
| 管理员/教务 | 打开课程与大纲 | 显示 7 条已核验官方来源；可新增学校实际课程规范 |
| 管理员/教务 | 新建测试草案排课版本 | 草案创建成功，不影响任何已发布版本 |
| 教师 | 打开我的课表 | 只能看到已发布课表；可维护本人可用时间 |
| 学生 | 打开我的选课 | 只能访问本人当前学年选课；无学段档案时给出明确提示 |
| 管理员 | 打开权限与审计 | 能看到关键配置和发布操作记录 |
| 运维 | 请求 `/api/health` | HTTP 200，数据库状态正常 |

  冒烟时不要用真实学生做删除、密码变更或无必要的数据修改。若需要验证写入，使用新建的测试草案对象，并在学校确认后再处理。

## 7. 回滚

  自动发布失败时脚本会恢复旧代码和停服时的最终数据库备份。若服务已健康但业务验收发现阻断问题，先停止继续录入，再按本次输出的 `ROLLBACK_APP` 和 `DATABASE_BACKUP` 路径执行人工回滚。

```bash
sudo systemctl stop alevelinfo
sudo rsync -a --delete /opt/alevelinfo/rollback/<发布编号>/app/ /opt/alevelinfo/app/
sudo rm -f /opt/alevelinfo/app/database.sqlite /opt/alevelinfo/app/database.sqlite-wal /opt/alevelinfo/app/database.sqlite-shm
sudo cp /opt/alevelinfo/backup/database.sqlite.pre-deploy-<发布编号>.bak /opt/alevelinfo/app/database.sqlite
sudo chown -R ubuntu:ubuntu /opt/alevelinfo/app
sudo systemctl start alevelinfo
curl --fail http://127.0.0.1:3001/api/health
```

  本次最终 `<发布编号>` 为 `20260830-225921`。回滚会丢弃该发布后产生的新写入，因此只有在业务负责人确认后执行；回滚前还应为当前数据库再创建一份一致性备份。

## 8. 发布后首周工作

- 教务核对当前学年并补录学生 9–12 年级与 IGCSE/AS/A Level 阶段。
- 课程负责人从 7 条官方来源开始，只录入学校实际开设的考试局、科目代码和有效版本。
- 教务配置开课、教学班、教师、教室和节次；教师维护不可用时间。
- 先生成草案并人工抽查学生、教师、教室和周课时，再发布正式课表。
- 每日检查数据库备份是否生成、完整性是否通过，并完成至少一次隔离目录恢复演练。

  本次没有引入多租户、微服务或自动抓取规则。若后续真实数据证明排课规模或并发写入超过单机能力，再单独评估成熟约束求解器或数据库升级，不与本次上线风险叠加。
