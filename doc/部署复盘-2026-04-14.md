# 部署复盘（2026-04-14）— 从本地 Windows 到公网可访问

本文是一次“按真实操作走完一遍”的复习笔记，适用于：**本机 Windows 开发（Vite + Express + SQLite/better-sqlite3）→ 轻量云 Ubuntu → 公网访问**。

你今天最终达成的线上形态：

```text
浏览器 → HTTP(80) → Nginx → 127.0.0.1:3001 → Node/Express（页面+API）→ SQLite 文件
```

> 说明：今天我们先跑通 **HTTP**；HTTPS 需要域名（证书不能给裸 IP 正常签发）。

---

## 一、选型与购买时的关键点

### 1) 为什么选 Ubuntu 22.04 LTS

- **资料最多**：Docker / Nginx / systemd / certbot 的教程与经验基本都默认 Ubuntu。
- **部署更省心**：命令更统一（`apt`）、踩坑少。

### 2) “镜像”是什么

- 云厂商的“镜像”就是**系统模板**（OS image），用来创建一台新实例。
- 不建议选 WordPress/面板类镜像作为应用服务器的起点（预装太多、排障更复杂）。

---

## 二、登录服务器：密码 vs SSH 密钥（你今天学到的核心概念）

### 1) 为什么建议用 SSH 密钥

- 密码登录在公网环境容易被扫描/爆破。
- 密钥登录更安全，也更适合后续自动化（脚本/CI）。

### 2) SSH 密钥是“文件”

在 Windows 上默认位置是：

- **私钥（必须保密）**：`C:\Users\<你>\.ssh\alevelinfo_ed25519`
- **公钥（放到服务器）**：`C:\Users\<你>\.ssh\alevelinfo_ed25519.pub`

> 私钥丢了怎么办：要么提前加“多把公钥”（多台电脑），要么把私钥加密备份；至少保留一个救援通道（云厂商控制台/TAT）。

### 3) 你今天遇到的两个典型坑

- **本机没 `.ssh` 目录**：导致 `Saving key ... failed: No such file or directory`  
  解决：先 `mkdir $env:USERPROFILE\.ssh`
- **第一次 SSH 提示指纹**：`Are you sure you want to continue connecting`  
  解决：确认 IP 属于你的服务器后输入 `yes`（写入 known_hosts）

## 三、系统更新中的“紫色界面”是什么

你在 `apt upgrade` 过程中看到的紫色界面属于系统升级交互提示（例如 needrestart）：

- **Pending kernel upgrade**：提示新内核已安装，需要 `sudo reboot` 才会生效
- **Which services should be restarted?**：提示哪些服务需要重启以加载新库

处理原则：

- 一般保持默认勾选，选择 `<Ok>`。
- 在还没部署业务前，建议直接 `sudo reboot`（重启成本最低）。

---

## 四、端口放行：云安全组 vs 服务器防火墙

你今天实际操作的是云厂商的端口规则（类似“防火墙/安全组”）：

- **放行**：22（SSH）、80（HTTP）、443（HTTPS）
- **不放行**：3001（应用端口不直接对外暴露）

> 服务器本机如果启用了 UFW，则也需要放行 80/443；很多云镜像默认 UFW 未启用。

## 五、Docker 安装踩坑与替代方案（你今天经历的关键问题）

### 1) 遇到的问题

你尝试走 Docker 官方源时，出现：

- `curl: (35) ... Connection reset by peer`
- `gpg: no valid OpenPGP data found`
- `NO_PUBKEY ...`

根因：服务器到 `download.docker.com` 的链路不稳定，导致 GPG key 拉取失败 → apt 仓库校验失败。

### 2) 你最终采用的可行方案

改用 Ubuntu 仓库安装：

- `docker.io` + `docker-compose`（Compose v1）

验证输出（你已看到）：

- `docker --version`
- `docker-compose --version`

并把当前用户加入 docker 组（避免每次 sudo）：

```bash
sudo usermod -aG docker $USER
newgrp docker
docker ps
```

> 注意：Compose v1 的命令是 `docker-compose ...`；Compose v2 才是 `docker compose ...`。

## 六、把源码从本机传到服务器（Windows 打包 + scp）

### 1) 为什么不传 `node_modules`

`better-sqlite3` 有原生模块，Windows 的 `node_modules` 不能直接在 Linux 上用，必须在 Linux 上 rebuild/安装。

### 2) 你今天的“最稳上传方法”

用 Windows 自带 tar 打包源码（排除 `node_modules`）：

```powershell
C:\Windows\System32\tar.exe -czf app-src.tgz --exclude="app/node_modules" app
```

上传：

```powershell
scp -i $env:USERPROFILE\.ssh\alevelinfo_ed25519 .\app-src.tgz ubuntu@<服务器IP>:/opt/alevelinfo/
```

服务器解压：

```bash
cd /opt/alevelinfo
tar -xzf app-src.tgz
```

## 七、构建与运行（Node/Express + Vite + better-sqlite3）

你今天在服务器上完成了：

- `npm ci` 安装依赖
- `npm run build` 生成 `dist/`
- `npm rebuild better-sqlite3` 让 native 模块适配 Linux
- `node server/index.js` 跑起后端（页面+API 一体）

健康检查（在服务器上）：

```bash
curl -I http://127.0.0.1:3001
```

看到 `HTTP/1.1 200 OK` 说明服务已可用。

## 八、Nginx 反向代理（对外只暴露 80/443）

你今天实现了：

- Node 只监听 `127.0.0.1:3001`（不对公网暴露）
- Nginx 监听 80，对外提供入口，然后反代到 `127.0.0.1:3001`

验证（看到 `Server: nginx/...` 就说明走到了 Nginx）：

```bash
curl -I http://127.0.0.1
```

## 九、systemd 守护：断开 SSH 也不会停（正式上线必做）

你今天做到了：

- `alevelinfo.service` **active (running)**
- `enable` 开机自启

常用命令：

```bash
sudo systemctl status alevelinfo --no-pager -l
sudo systemctl restart alevelinfo
journalctl -u alevelinfo -n 200 --no-pager
```

### JWT_SECRET 的重点

- `JWT_SECRET` 必须是**强随机**，且上线后尽量固定（否则用户 token 失效，需要重新登录）。
- **不要把真实密钥发给任何人，也不要提交到仓库。**

## 十、域名 / HTTPS / 备案：什么时候需要

### 1) 小范围内测：可以先不用域名

- 直接用 `http://<公网IP>` 即可访问。
- 但这意味着：**没有 HTTPS**（传输明文）。

### 2) 想要 HTTPS：需要域名

- 证书通常不为裸 IP 签发，必须有域名并解析到服务器。
- 域名注册通常需要实名。

### 3) 是否需要备案

常见规则（以你服务器在中国大陆为例）：

- 用域名对外长期提供网站服务，一般需要 ICP 备案流程。

## 十一、推荐的“标准部署流程”清单（复习用）

你可以把下面当成以后每次上线的顺序：

- **购买与初始化**
  - 选 Ubuntu LTS
  - 云端放行端口：22/80/443
  - SSH 登录成功
  - 配 SSH key（公钥放服务器，私钥留本机）
- **系统准备**
  - `apt update && apt upgrade`
  - 必要时 `sudo reboot`
- **代码上云**
  - 上传源码（不含 node_modules）
  - 服务器解压到 `/opt/alevelinfo/app`
- **构建与依赖**
  - `npm ci`
  - `npm run build`
  - `npm rebuild better-sqlite3`
- **运行与托管**
  - systemd 托管 node 服务
  - Nginx 反代到 `127.0.0.1:3001`
- **验证**
  - `curl -I http://127.0.0.1:3001`
  - `curl -I http://127.0.0.1`
  - 浏览器访问公网 IP
- **安全与数据**
  - 固定 `JWT_SECRET`
  - 不暴露 3001
  - SQLite 备份（每日 + 保留周期 + 恢复演练）
- **可选增强**
  - 域名 + HTTPS（certbot）
  - 日志/监控/告警
